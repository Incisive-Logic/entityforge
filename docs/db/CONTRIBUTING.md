# Contributing

## Build and test

Follow [building from source](../developer/building.md). Run the tests for the components affected by your change. Include regression coverage when fixing behaviour.

## Changes

Keep changes focused. Explain the problem, the resulting behaviour and how you verified it. Update user instructions and API documentation when changing a public contract or workflow. Follow the [shared formatting rules](../developer/formatting.md) and preserve generated and third-party files.

Preserve repository formatting conventions and existing third-party notices. Record the source and applicable licence when introducing third-party material. Do not include credentials, personal data or local database files in a contribution.

## Community

Follow the [code of conduct](CODE_OF_CONDUCT.md). See [security](SECURITY.md) for the server's security model and the [reporting policy](../../SECURITY.md) to report vulnerabilities privately.
